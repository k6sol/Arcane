# Release acceptance

## A release must demonstrate

- First-run setup and subsequent launches retain the intended account, project and settings.
- A human message reaches the selected supported model once; drafts/history survive switches and restart.
- Original asset generation produces inspectable artifacts; approval, conversion and import preserve exact mappings.
- Task/test/repair outcomes reflect actual evidence and retain uncertainty safely.
- Updates preserve user data; startup failures expose recovery without replaying work.
- The plugin package is attributable and compatible with the app.
- Diagnostics explain the failing stage without exposing credentials.

Public commercial release additionally needs configured authentication, MFA, administration, billing and distribution requirements. [[Delivery/G09 Accounts and Billing]] holds those criteria.

Record native Studio acceptance as missing while Studio operation is outside authorization. Hosted fixtures do not check that box. [[Operations/Evidence Ledger]] and [[Delivery/G10 Customer Release]] own the proof.
