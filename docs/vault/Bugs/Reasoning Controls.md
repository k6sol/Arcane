# Reasoning controls

The composer and pop-out bar each mapped High, Extra high and Max onto the same three dots; Ultra had no mapping. Both now use six consistent levels: Low/Minimal1, Medium2, High3, Extra high4, Max5, Ultra6. Inactive dots remain muted; unknown efforts remain unscored instead of inventing support. The visible composer word expands xhigh to Extra high. Native effort identifiers and the provider's actual reported choices remain unchanged.

Saved Codex model/effort presentation is available while the native snapshot loads, so a remembered pair does not flash Choose model during connection. Its accessible label says Saved and Waiting for connection verification; controls and Send still require actual readiness. When a fresh catalog excludes that pair, the unavailable-choice guard still applies: a stale saved model is not shown as available or silently replaced.

Strict660 compilation and the final294-case frozen native/browser selection pass include the existing real Edge range input/change, reset, keyboard, thumb geometry and rendered gradient checks, plus saved disconnected label/admission and all four higher effort dot/color checks. Both providers' native catalog boundaries remain intact. An earlier38-case run passed36 and failed2: saved presentation was initially also shown for a fresh catalog that excluded the pair, and extra rendered-dot assertions shifted an existing sprite animation geometry observation. The implementation now shows a saved-only pair only without a native snapshot; the extra assertions run after the original unchanged geometry checks. The original failed receipt is retained. No timeout, geometry expectation or native admission check was weakened.

This is source/browser verification, not installed customer acceptance. The f8 customer package predates these controls. [[Bugs/Provider Startup Latency]] addresses the expensive startup scan separately.
