# Production skill upgrade

The 30 October brief requires a substantive revision of every Arcane product skill. Full-game requests must deliver a coherent playable game with the appropriate content depth, original art, systems, interface, animation and relevant VFX/SFX. Racing is one example. A focused edit remains focused. Instructions are guidance, not model training or evidence of an exceptional finished game.

Root owns registry integrity, metadata and actual runtime routing. All 62 entries and their declared references were source-audited. Experimental/approval status is preserved until real evaluation justifies a change. Rewrites must be loaded by the real platform within existing context limits, rather than becoming unused vault documents.

## Completion gates

- [x] Inventory all 62 current entrypoints and declared references against exact Git hashes.
- [ ] Substantially improve every entrypoint with its own domain methods, integration contracts and real acceptance criteria.
- [ ] Reconcile referenced recipes/blueprints so they support the new complete-game standard without being misrepresented as finished output.
- [ ] Validate every changed skill's format, registry/reference hashes and actual bounded recommendation/load behavior.
- [ ] Route broad requests to a production director, genre and staged cross-discipline work even when the prompt does not list every discipline.
- [ ] Preserve focused scope, actual tool limits, original Blender authoring, source ownership, reviews and truthful unknown/failure states.
- [ ] Verify representative full-game, natural-scene, character, systems and UI prompts on actual output. A passing keyword test does not prove game quality.
