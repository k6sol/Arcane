# Investigate a failure

Capture the trigger, expected outcome, actual outcome, source/app/plugin revision and safe correlated evidence. Reproduce at the boundary that failed. Distinguish source defects, stale installed builds, provider failures, unknown dispatch and cleanup failures.

Read the original error before changing code. Preserve its identity and relevant cause; do not classify authority from error-message text. Fix the narrow cause, repeat the original reproduction and check adjacent ownership/recovery behavior. Log a useful result even if an external service still prevents completion.

Use [[Templates/Bug]] and attach the result to the relevant delivery goal. No passwords, keys or raw sensitive prompts belong in the report.
