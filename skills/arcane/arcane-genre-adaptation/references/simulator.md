# Collection / progression simulator

The player chooses an activity, tool or area with a useful efficiency/risk/capacity trade-off. This profile is for collection simulators, not every game called a simulation. A flight/vehicle/physical simulation should use its actual domain mechanics instead of an imposed sell-and-rebirth loop.

## Make repetition change meaningfully

Prove one satisfying activity, return/sell if applicable and an upgrade that changes play. For a full request, build the promised later activities, locations and goals with distinct traversal, resource behavior or tool decisions. Higher health and larger rewards alone do not make a new zone. Pets, eggs, trading and rebirth are optional supporting systems, not a mandatory checklist.

The server validates current node/actor, allowed area, range, rate, capacity and equipped tool before reward. Handle depletion/respawn once and cancel old callbacks on zone unload. Gates must enforce reward eligibility server-side even if clients hide collision. Requested saves, resets and optional pet equipment share actual profile ownership; a follower visual cannot grant a bonus. Random paid mechanics need their separate current policy/commerce checks.

## Feel, readability and proof

Tie the real tool windup/contact/recovery to resource reaction, inventory change, sound and restrained VFX. Clearly show capacity, a useful next purchase and why an action is unavailable. Art should distinguish interactable resources and locations without smothering the task in coins or pet effects. Use actual authorized media; no effect or asset name is an implementation by itself. `arcane-simulator-kit` provides composition details, with economy/inventory/gameplay-feel companions.

Play collect -> full capacity -> sell/return -> upgrade -> changed activity, then a later progression branch. Test remote spam, locked-zone rewards, simultaneous depletion, duplicate sale and interrupted reset/save. Compare calculated time-to-unlock with actual movement/action time. Observe whether repeated actions and upgrades remain informed and satisfying; a rapidly increasing number and a functioning shop cannot establish fun, content completeness or retention.
