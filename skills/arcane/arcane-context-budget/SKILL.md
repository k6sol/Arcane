# Reduce repetition, not the requested outcome

## Build a decision-sized working set
Start with the actual task and selected skill metadata. Load the relevant entrypoints, callers and conditional references, then retrieve exact spans that decide the next change. A broad complete-game task needs a coverage map across its loop, content and presentation; a focused bug needs its affected chain, not all skills.

Keep a compact contract ledger: authoritative owner, input/output, lifecycle, content IDs, source revision, asset dependencies and observable acceptance. Expand a seam when another system depends on it. Do not compress away the distinction between server truth, client presentation and durable state, or omit denied/cleanup paths to save tokens.

Use `skills_get` for selected bodies/references and bounded scene/script searches. Narrow truncated results instead of dumping the whole place. Reuse unchanged reads with provenance; refresh a source baseline before an edit after conflict/change. A summary is a navigation aid, never expectedSource.

## Make artifacts carry the bulk
Keep large logs, screenshots, model files and manifests as artifact references with selected findings. Do not paste base64 or an entire generated asset into chat when an exact artifact plus hash/path is available. Record expected versus observed values and the relevant error/line rather than every successful poll.

Batch independent bounded reads when useful. Keep dependent mutations sequential so their outcomes can change the next action. Use a deterministic helper for repeated transformations only when its actual contract and output are understood; a helper's existence is not proof of correctness. Do not hide unresolved commands behind a compact success summary.

## Handoff without losing the game
A durable checkpoint contains objective and scope, current target/revision, completed artifacts, actual verification, unresolved dependencies/failures and the next acceptance action. For complete-game work, include remaining content, GUI and relevant animation/VFX/SFX integration explicitly. Mark a placeholder as incomplete; never rename a reduced deliverable Complete to fit the remaining context.

Preserve manual work, permissions, unknown acknowledgements and original operation identities. Later turns acquire fresh authority where required; historical metadata cannot carry live grants. Avoid serializing secrets or raw private conversations into shared notes.

## Evaluate useful efficiency
Measure bytes and provider-reported tokens only where available, with no exact byte-to-token or hidden-quota claim. Compare acceptance completion, rework, regressions and elapsed time. A smaller prompt that loses a dependency or forces the user to repeat instructions is a regression. Keep the user's model/effort choice intact and disclose what remains unknown.
