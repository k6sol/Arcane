# Responsiveness and gameplay polish

## Define timing at use scale
Break an action into anticipation, commitment, feedback and recovery. Measure input-to-visible response and authoritative acknowledgement where possible. Identify which delay supports the intended challenge and which is friction.

Tune camera, animation, audio, effects and UI as one action, not isolated decorations. Confirm hit/use feedback corresponds to the actual server result. Prediction must reconcile cleanly. Use variation for purpose rather than constant shake, bloom and particles.

Make failure legible and retry quick enough for the chosen genre. Include success feedback without interrupting control unnecessarily. Preserve difficulty and user art direction; polishing is not permission to change the core mechanic.

## Verification
Compare recordings and test traces before/after at normal and low frame rates. Exercise interrupted input, rapid repeats and denied actions. Get player observations about control, readability and frustration. Record tunable values and evidence; avoid calling an effect stack 10/10 without seeing it in actual play.
