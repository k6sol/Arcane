# Arcane release evidence

Identify exact source, app/plugin/package revisions and installed identity. Do not infer installation from a successful push. Check source signatures separately from distributable signing/installer requirements.

Run relevant verification once against the actual change, then inspect failures before expanding. Poll a confirmed live exact job instead of restarting it because observation timed out. Keep build/resource gates and original per-operation proof requirements intact.

Exercise update banner, draft persistence, restart, startup failure recovery, authentication retention and compatibility in an authorized isolated environment. Preserve the user's running application unless closure is authorized. Never label a controlled fixture as an authenticated customer journey or native Studio test.

Record actual artifact and run links, failure/remaining limitations and rollback/recovery. Publish concise signed commits with necessary validation; update the vault only with claims supported by the evidence.
